대상: $ARGUMENTS

1. 첫 보고 (5분 안)
   - 무엇이 안 되는지, 영향 범위(회원/비회원, 화면), 언제부터
   - 내부 문서·개인정보 노출이면: 노출 파일과 주소, 즉시 막는 방법(배포물 격리 재배포, 롤백), 검색엔진 삭제 요청 필요 여부
   - runbook.md의 롤백 절차와 함께 "롤백 / 핫픽스" 중 무엇을 할지 묻는다 (10분 안에 원인을 못 찾으면 롤백 권장)
2. 핫픽스로 가면
   - 작업 브랜치 `work/hotfix-요약`
   - developer(핫픽스): 원인만 고친다. 근처 정리·개선 금지. 수정 한도 2회, 넘으면 롤백 재권고
   - qa: 해당 결함 + `bash scripts/check.sh` 전체
3. 배포 승인 요청 → 사람이 배포 → "배포 완료" → release(출시 후 확인 모드)
4. docs/ops/incidents.md
```
## [P0/P1] 제목 · 발생 YYYY-MM-DD HH:MM · 해결 HH:MM
- 증상 / 영향 / 원인 / 조치(롤백·핫픽스) / 재발 방지 (검사 추가, 점검표 항목 추가, 구조 변경 등)
```
5. 재발 방지 작업은 ops로 분류해 다음 릴리스 후보로. 검사로 막을 수 있는 문제면 check.d 스크립트 추가를 architect에게 제안
6. stage.md 버전 v1.0.x
