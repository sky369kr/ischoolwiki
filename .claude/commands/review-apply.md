---
description: docs/reviews/의 교차 검토 결과를 읽고 항목별로 반영/보류/기각을 판단해 해당 에이전트에게 넘긴다. 인자로 대상(prd, architecture, 기능 ID)을 준다.
---

대상: $ARGUMENTS

1. docs/reviews/에서 대상의 최신 result 파일을 읽는다. 없으면 저장 경로를 안내하고 멈춘다.
2. 지적마다 판단표. 다른 AI 의견은 정답이 아니라 제안이다. 기준 문서와 실제 코드를 직접 확인해서 판단한다.
```
| 번호 | 지적 요약 | 사실 확인 결과 | 판단(반영/보류/기각) | 이유 | 담당 |
```
   - 반영: 사실이고 현재 범위 안에서 고칠 가치가 있음
   - 보류: 맞지만 범위 밖 → backlog.md (범위 동결 중이면 결함이 아닌 것은 모두 보류)
   - 기각: 사실과 다르거나 기준 문서와 충돌 (근거 명시). 치명 지적을 기각할 때는 근거를 특히 분명히.
3. 판단표를 보여주고 승인을 받는다.
4. 승인 후
   - prd → planner(변경 모드), 문서 수정 횟수 +1
   - architecture → architect, 문서 수정 횟수 +1
   - 기능 → tasks.md "수정 필요"로 developer에게 (수정 횟수 +1, 메모에 리뷰 파일)
   - 기능 검토에서 반영할 것이 없으면 → "사람 확인 대기"(공개 페이지면 "SEO 감사 대기")
5. result 파일 끝에 판단표, stage.md 교차 검토 기록 "반영 완료", decisions.md 기록
6. "다음 /build에서 이어서 진행합니다"
