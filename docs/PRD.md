> 이 문서는 /adopt 역기획 초안이다. 이미 운영 중인 코드(`src/`), README.md "현재 상태와 남은 일", docs/decisions.md, docs/adopt-report.md에서 현재 동작을 정리했다.
> start.md의 2~7번(사용자, 사업 목표, 필수 기능, 하지 않을 것, 공개 구분, 노출 질문)이 비어 있어서 그 부분은 추정으로 채웠다. **추정한 내용에는 모두 "(추정)"을 붙였다.** 사람이 정해야 할 것은 맨 끝 "열린 질문"에 모았다.

## 1. 배경과 문제
- 아시아 국제학교의 학비·교육과정·입학 정보는 학교 사이트, PDF, 뉴스 게시판에 흩어져 있고, 제3자 사이트에는 출처가 없거나 오래된 값(할인 후 금액, 추정치)이 섞여 있다. (decisions.md 2026-11-13 BST 항목: myispp의 BST 학비는 제3자 출처이고 할인·점심 포함 금액이라 쓰지 않음)
- 부모가 검색 엔진이나 AI 답변(ChatGPT, Claude, Perplexity 등)으로 학교를 알아볼 때, 출처가 분명한 영어 참고 자료가 적다. (추정)
- 이 사이트는 학교가 직접 공개한 자료만 근거로 학교 프로필과 글을 자동으로 만들고, 모든 숫자에 출처를 붙여 이 빈자리를 채운다.
- 운영사는 같은 회사 이름으로 국제학교에 유료 AI 가시성(AEO/GEO) 서비스(브랜드 36.9°)를 판다(`src/operator.ts`). 파일럿 3개 학교 중 2곳이 고객이다. 이 사이트는 고객 학교의 공개 자료가 검색·AI 답변에 정확히 인용되도록 돕는 수단이기도 하다. (추정: 사업상 역할은 코드와 공개 문구에서 읽은 것이며 사람이 확인해야 함)

## 2. 대상 사용자

### 주 사용자: 전 세계 영어권 부모 (decisions.md 2026-11-12 결정)
- 상황: 자녀의 아시아 국제학교 진학·전학을 알아보는 중. 구글 검색이나 AI 답변으로 "학비가 얼마인가", "어떤 교육과정인가", "기숙이 되는가"를 묻는다. (상황 세부는 추정)
- 지금의 해결 방식: 학교 사이트를 하나씩 열어 보거나, 출처가 불분명한 비교·순위 사이트, 커뮤니티 글을 본다. (추정)
- 불편한 점: 숫자의 출처와 기준 학년도가 불분명하고, 학교 PDF·뉴스를 직접 찾아 읽어야 한다. (추정)

### 보조 사용자 1: 고객 학교 (운영사 서비스 이용 학교)
- 상황: 자기 학교의 공개 정보가 검색·AI 답변에 정확히 나오기를 원한다. (추정)
- 이 사이트에서 기대하는 것: 학교가 공개한 내용을 담담하게 전하는 글이 꾸준히 올라오는 것, 학교당 7~10편 정도의 초기 글(decisions.md 2026-11-13 "처음 글 채우기").

### 보조 사용자 2: 운영자 (사람)
- 상황: 매일 자동 실행 결과를 확인하고, 문제 글을 내리고, 학교·학비 자료를 추가한다.
- 불편한 점(adopt-report.md): 보류 글은 API로만 볼 수 있고, 글 교체가 사람 손 3단계(내리기 → 원격 DB에서 소식 되돌리기 → 실행)다.

### 보조 사용자 3: 검색 엔진·AI 크롤러
- 사람이 아니지만 사이트의 목표(검색·AI 답변 노출)에 직접 연결되므로 기능 요구사항(F-08)에 반영했다.

## 4. 핵심 사용자 시나리오
- **S-01** 영어권 부모는 특정 학교의 학비를 검색하거나 AI에 물은 상황에서, 검색 결과·AI 답변의 링크로 학교 프로필이나 학비 안내 글을 열어, 학년별 연간 학비와 그 숫자의 학교 공식 출처를 확인한다.
- **S-02** 영어권 부모는 한 도시의 국제학교를 알아보는 상황에서, 첫 화면의 도시 링크나 도시 비교 페이지를 열어, 그 도시 학교들의 교육과정·학년 범위·학비 범위를 함께 보고 학교 프로필로 이동한다.
- **S-03** 영어권 부모(또는 한국어 독자)는 학교 소식을 알고 싶은 상황에서, 글 목록이나 학교 프로필의 글 링크를 열어, 요약("In short")·본문·FAQ·출처 목록이 있는 글을 읽는다. 고객 학교의 글이면 운영사와의 관계를 함께 본다.
- **S-04** 운영자는 매일 자동 실행(01:17 UTC) 뒤에, 학교 뉴스 수집 → 사실 추출 → 글 작성 → 검증 → 번역이 끝나 검증을 통과한 글만 자동 게시되고, 보류된 글은 알림과 `/admin/held`로 확인한다.
- **S-05** 운영자는 게시된 글에서 문제(출처 오인용, 학생 실명 등)를 발견한 상황에서, `/admin/unpublish`에 글 번호 또는 실행 번호를 보내, 영어 글과 번역을 함께 공개 화면에서 내린다.

## 5. 기능 목록

> 각 기능의 "현재 상태"는 adopt-report.md와 코드 기준이다(동작 / 부분 / 깨짐).
> 수용 기준은 현재 코드가 하는 일을 관찰 가능한 문장으로 옮긴 것이다. 현재 코드가 기준을 만족하는지는 qa가 확인한다.

### 콘텐츠 원칙 (모든 기능 공통, decisions.md 결정 정리)
1. **학교가 공개한 자료만**: 페이지에 나오는 학교 사실(숫자·이름)은 D1 `facts`에 출처와 함께 기록된 것만 쓴다. 추정·보간·계산값·제3자 사이트 값 금지. 학비 기본 팩트는 학교 자체 도메인 출처일 때만 받는다.
2. **학생 실명 금지**: 학생·졸업생·가족의 개인 이름은 학교가 공개했더라도 쓰지 않는다. 역할로 나오는 교직원 이름은 허용. (2026-11-13)
3. **평가·비교 금지**: 칭찬·비판 같은 평가, 다른 학교와의 우열 비교를 쓰지 않는다. 비교 페이지는 같은 항목을 나란히 놓을 뿐 순위·추천을 하지 않는다. 자료에 없는 내용은 부모에게 꼭 필요한 것만 끝부분에 한두 문장으로 중립적으로 언급한다.
4. **고객 관계 공개**: 운영사의 유료 서비스 고객인 학교는 그 학교의 프로필·글 페이지에 관계를 밝힌다. 운영자 정보 페이지에 운영사와 서비스 브랜드를 밝힌다.
5. **검증을 약하게 만들지 않는다**: 규칙 검증과 근거 검사를 통과하지 못한 글은 게시하지 않는다(fail closed). 검증을 약하게 바꾸는 변경은 고위험이며 교차 검토 필수(CLAUDE.md 10-1).
6. **학교 사진 없음**: 저작권 때문에 학교 사진을 넣지 않는다.

### 공개 화면

#### F-01 첫 화면
- 설명: 학교 카드(도시·국가, 교육과정, 학년 범위, 학비 범위), 도시별 비교 링크, 최신 영어 글 6편, 신뢰 안내 3줄(출처 표시, 게시 전 검증, 매일 읽기).
- 관련 시나리오: S-01, S-02 / 관련 화면: P-01
- 우선순위: 필수(후보) / 위험도: 일반 / 현재 상태: 동작
- 수용 기준:
  - [ ] `/`를 열면 상태 200, h1이 1개다.
  - [ ] 활성 학교(`schools.active = 1`)마다 카드가 1개 있고, 카드의 학교 이름이 `/wiki/{slug}`로 연결된다.
  - [ ] 카드의 학비 범위 옆에 출처 링크가 있고, 근거 팩트가 없는 항목(교육과정·학년·학비)은 카드에 표시되지 않는다.
  - [ ] 고객 학교(`is_client = 1`) 카드에만 "Client of the site's operator" 표시가 있고 `/about`으로 연결된다.
  - [ ] 도시 링크마다 `/compare/{city_slug}-international-schools`로 연결되고 학교 수가 표시된다.
  - [ ] 최신 글 영역에 게시된 영어 글이 최대 6편, 최근 게시순으로 나온다. 글이 없으면 "No articles yet."이 나온다.
  - [ ] 375px 화면에서 가로 스크롤 없이 표시된다. (추정: 반응형 기준은 design-spec에서 확정)
- 예외 상황: 학교 0곳(빈 카드 영역) / 글 0편("No articles yet.") / DB 오류(500 "Server error")

#### F-02 학교 프로필
- 설명: `/wiki/{slug}`. 상단 요약표(위치, 교육과정, 학년, 연간 학비+출처, 공식 사이트, 기록된 사실 수), 고객 문구, 이 학교 영어 글 목록(최대 20), 기록된 사실 전체 표(항목·값·기준일·출처).
- 관련 시나리오: S-01, S-02 / 관련 화면: P-02
- 우선순위: 필수(후보) / 위험도: 일반 / 현재 상태: 동작
- 수용 기준:
  - [ ] 활성 학교 slug로 열면 상태 200, h1이 학교 이름이다.
  - [ ] 없는 slug나 비활성 학교 slug로 열면 상태 404 "Page not found"가 나온다.
  - [ ] "All recorded facts" 표의 모든 행에 출처 링크(`rel="nofollow noopener"`)가 있다.
  - [ ] 요약표의 교육과정·학년·학비는 `facts`에서 계산된 값만 나오고, 근거가 없으면 그 행이 없다.
  - [ ] 경로 표시(Home › 도시)의 도시 링크가 그 학교의 도시 비교 페이지로 연결된다.
  - [ ] 페이지 HTML에 EducationalOrganization JSON-LD가 있다.
- 예외 상황: 사실 0건("No verified facts recorded yet.") / 글 0편("No articles yet.") / 잘못된 slug(404)

#### F-03 도시 비교
- 설명: `/compare/{city_slug}-international-schools`. 그 도시 활성 학교 카드(이름순), 학교가 2곳 이상이면 두 학교 이상에 공통으로 있는 사실 항목을 나란히 놓은 표.
- 관련 시나리오: S-02 / 관련 화면: P-03
- 우선순위: 있으면 좋음(후보) / 위험도: 일반
- 현재 상태: 부분 — 파일럿 3개 학교가 각각 다른 도시(베이징, 다롄, 타슈켄트)라 지금은 모든 비교 페이지에 학교가 1곳뿐이고 "Side by side" 표가 나오지 않는다.
- 수용 기준:
  - [ ] 활성 학교가 있는 도시 slug로 열면 상태 200, h1이 "International schools in {도시}"다.
  - [ ] 활성 학교가 없는 도시 slug는 404다.
  - [ ] 학교가 2곳 이상인 도시에서는 "Side by side" 표가 나오고, 값이 없는 칸은 "—"로 표시된다.
  - [ ] 표와 문구에 순위·점수·추천 표현이 없다(콘텐츠 원칙 3).
  - [ ] 페이지 HTML에 ItemList JSON-LD가 있고 학교마다 `/wiki/{slug}` URL이 들어 있다.
- 예외 상황: 학교 1곳(표 없이 카드만) / 공통 항목 0개(표의 열이 학교 이름뿐)

#### F-04 글 페이지 (영어)
- 설명: `/blog/{slug}`. 경로 표시, 제목, 게시일·학교·출처 수, 고객 문구, "In short" 요약 상자, 본문(마크다운 표는 HTML 표로), FAQ("Questions parents ask"), 출처 목록, 학교 요약 상자.
- 관련 시나리오: S-01, S-03 / 관련 화면: P-04
- 우선순위: 필수(후보) / 위험도: 일반 / 현재 상태: 동작
- 수용 기준:
  - [ ] `status = 'published'`인 영어 글 slug로 열면 상태 200, h1이 글 제목이다.

- 우선순위: 있으면 좋음(후보) / 위험도: 고위험(외부 연동, 검증 흐름 변경) / 현재 상태: 동작
- 수용 기준:
  - [ ] 중복(`duplicate`), 짧은 본문(`empty`), 근거 검사 실행 실패가 하나라도 있으면 고쳐 쓰지 않고 바로 보류된다(`canRevise` 단위 테스트).
  - [ ] 고쳐 쓴 글은 같은 규칙 검증과 근거 검사를 다시 거치고, 남은 문제가 있으면 보류된다.
  - [ ] 고쳐 쓰기가 일어난 글마다 `article_revisions`에 처음 초안과 처음 지적이 1행 있다.
  - [ ] 고쳐 쓰기는 글당 최대 1회다.
- 예외 상황: 고쳐 쓰기 API 실패(write 단계 실패로 보고)

#### F-16 주제별 안내 글
- 설명: `src/guides.ts`. 그날 쓸 새 소식이 없으면 기록된 사실로 학비 → 교육과정 → 기숙 → 입학 순서 중 아직 시도하지 않았고 사실이 3건 이상인 주제 하나로 안내 글을 쓴다. 안내 글은 그 주제의 사실만 보고, 같은 검증(F-13·F-14·F-15)을 거친다. 학교·주제마다 한 번만 시도(`guide_attempts`).
- 관련 시나리오: S-01, S-04 / 관련 화면: P-04
- 우선순위: 있으면 좋음(후보) — 단, 고객 학교 글 채우기(decisions.md 2026-11-13)와 학비 질문(S-01)에 직접 연결되어 필수로 올릴지 사람 판단 필요(Q1)
- 위험도: 고위험(외부 연동, 공개 콘텐츠 정확성) / 현재 상태: 동작
- 수용 기준:
  - [ ] 쓰지 않은 소식이 있는 날에는 안내 글을 쓰지 않는다.
  - [ ] 주제 사실이 3건 미만인 주제는 시도하지 않는다.
  - [ ] 같은 학교·같은 주제는 결과(게시·보류·건너뜀)와 상관없이 `guide_attempts`에 1행만 있고 다시 시도되지 않는다.
  - [ ] 안내 글의 근거 검사 재료에는 그 주제의 사실만 들어간다(다른 주제 숫자가 나오면 보류).
- 예외 상황: 네 주제 모두 시도 완료("no new material; nothing written")

#### F-17 한국어 번역
- 설명: 검증을 통과한 영어 글만 한국어로 번역하고, 번역본도 숫자 검증(규칙 검증)을 다시 거친다. 영어와 같은 slug, `translation_of`로 원본 연결.
- 관련 시나리오: S-03 / 관련 화면: P-06, P-07
- 우선순위: 있으면 좋음(후보) / 위험도: 고위험(외부 연동) / 현재 상태: 동작
- 수용 기준:
  - [ ] 보류된 영어 글은 번역되지 않는다.
  - [ ] 번역본에 영어 원문·팩트·재료 날짜에 없는 숫자가 있으면 번역본만 보류되고 영어 글은 그대로 게시된다.
  - [ ] 번역본의 `translation_of`가 원본 영어 글 id다.
- 예외 상황: 번역 API 실패(그 학교 write 단계 실패로 보고)

#### F-18 자동 게시, 월 한도, 보류 알림
- 설명: 검증 통과 글은 `AUTO_PUBLISH = "true"`면 `published`, 아니면 `verified`. 보류 글은 `held`, `ALERT_WEBHOOK_URL`로 알림. 학교당 한 달(UTC) 영어 글(verified·published) 수가 `MAX_POSTS_PER_SCHOOL_PER_MONTH`(현재 12) 이상이면 쓰지 않는다. 모든 상태 변화는 `article_events`에 남는다.
- 관련 시나리오: S-04 / 관련 화면: 없음
- 우선순위: 필수(후보) / 위험도: 고위험(공개 범위 결정, 외부 연동 알림) / 현재 상태: 동작(`AUTO_PUBLISH = "true"`, 2026-11-13 운영자 결정)
- 수용 기준:
  - [ ] `AUTO_PUBLISH = "false"`면 검증 통과 글이 `verified`로 저장되고 공개 화면·sitemap에 나오지 않는다.
  - [ ] `AUTO_PUBLISH = "true"`면 검증 통과 글이 `published`와 게시 시각으로 저장되고 공개 화면에 나온다.
  - [ ] 보류 글은 공개 화면·sitemap·RSS·llms.txt 어디에도 나오지 않는다.
  - [ ] 그 달에 이미 한도만큼 쓴 학교는 보고에 `monthly limit reached`가 남고 글이 저장되지 않는다.
  - [ ] 저장되는 모든 글에 `verification_results` 1행과 `article_events` 1행이 생긴다.
  - [ ] 보류 시 `ALERT_WEBHOOK_URL`이 있으면 글 id·학교·문제 목록이 전송된다. 알림 실패는 실행을 멈추지 않는다.
- 예외 상황: 알림 주소 없음(알림 없이 보류만) / 알림 전송 실패(무시)
